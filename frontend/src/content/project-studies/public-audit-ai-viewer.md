> 공개 감사 결과 약 **1만 5천 건**을 AI로 분류하고, 분야·업무·지역 기준으로 조회와 통계를 제공한 시스템입니다.

감사원 연구 과제로 개발했습니다. 한림대학교 지능형의사결정시스템 연구실 (LIT LAB). 3인 팀 프로젝트이며 백엔드와 데이터 파이프라인을 담당했습니다.

## 담당 범위와 구현

- **분류 기준과 프롬프트:** 감사사항을 분야 → 업무 → 세부업무로 분류하도록 프롬프트를 구성하고, 결과를 실무자 라벨과 나란히 검토할 수 있게 했습니다.
- **조회 백엔드:** FastAPI로 조건 검색·통계 집계·원문 연결 API를 구축하고 AWS에 배포했습니다.
- **기관 협의와 인계:** 감사원 담당자와 요구사항 및 검토 결과를 조율하고, 사용 후 소스코드와 실행 절차를 인계했습니다.

아래의 약 1만 5천 건은 **시스템에 구축한 공개 감사 결과의 규모**이며, 분류 일치율은 별도 136건 표본의 평가입니다.

![공공 감사 결과분석 시스템 첫 화면](/projects/AUDIT/audit-home.png)

보유한 JSON을 별도 Docker PostgreSQL에 적재하고 원본 FastAPI와 React 화면을 로컬에서 실행해 캡처했습니다.

캡처에 사용한 JSON과 약 1만 5천 건 구축 규모는 집계 범위가 다릅니다.

## 📌 무엇을 해결하나

감사 실무자가 과거 사례를 찾을 때 **분야나 업무 기준이 없어** 선별에 시간이 걸렸습니다. 감사 결과는 공개돼 있지만 기관별·연도별로 흩어져 있고, 제목만으로는 어떤 업무에 관한 사례인지 알기 어렵습니다.

그래서 흩어진 감사 결과를 모아 **일관된 분류 기준으로 라벨을 붙이고**, 비전공자도 쓸 수 있는 조회·통계 화면을 만들었습니다.

## 🔄 데이터 파이프라인

```
공개 감사 결과 수집
   │
   ├─ 정제 · 중복 제거 ──── 파일 해시 기반. 같은 문서가 여러 경로로 들어와도 한 건으로
   │
   ├─ AI 자동 분류 ──────── GPT-4.1-mini를 배치 스크립트로 일괄 호출
   │                       분야(category) → 업무(task) → 세부 업무 3단계
   │
   ├─ 이중 저장 ─────────── AI 분류 결과와 실무자 라벨링 원본을 컬럼으로 분리
   │                       원본을 덮어쓰지 않아 언제든 대조 가능
   │
   └─ 피드백 반영 ───────── 실무자 검토 결과로 분류 체계 자체를 개정
   │
   ▼
PostgreSQL 적재 · 원문 PDF는 S3 보관
```

### 왜 원본을 따로 남겼나

AI가 붙인 라벨이 실무자 판단과 다를 수 있습니다. 한 컬럼에 덮어쓰면 **어디가 어떻게 틀렸는지 추적할 수 없어** 분류 체계를 개선할 근거가 사라집니다.

두 값을 나란히 보관했더니 실무자 피드백을 모아 **분류 기준 자체를 고치는** 작업이 가능해졌습니다.

### 왜 배치인가

1만 5천 건을 건건이 호출하면 시간과 비용이 모두 커집니다. 문서를 묶어 배치 스크립트로 일괄 처리하고, 중단 지점부터 이어서 돌릴 수 있게 구성했습니다.

> 분류는 **적재 이전에 한 번 수행하는 별도 배치 작업**이라 이 저장소에는 포함하지 않았습니다. 여기 있는 코드는 분류가 끝난 데이터를 제공하는 API와 화면입니다.

## 검증 및 성과

공개 감사 결과 약 **1만 5천 건**을 분류·조회할 수 있도록 구축하고 AWS에서 운영한 뒤 소스코드와 실행 절차를 인계했습니다.

최종 평가표의 전처리된 **136건 표본**에서 GPT 분류와 후처리 적용 후 기준 라벨과 일치한 결과입니다. 백분율은 확인된 일치 건수를 136으로 나눠 소수 첫째 자리로 반올림했습니다.

| 분류 단계 | 기준 라벨과 일치 | 일치율 |
|---|---:|---:|
| 분야 | **121/136** | **89.0%** |
| 업무 | **108/136** | **79.4%** |
| 세부업무 | **65/136** | **47.8%** |

세부업무의 낮은 일치율과 함께 상위 개념으로의 일반화, 잘못된 매핑과 번호 체계 오류 등이 관찰됐습니다. 분류 범위·기준의 모호성도 한 원인일 수 있습니다.

## 한계와 회고

136건 결과를 약 1만 5천 건 전체의 정확도로 확대하지 않습니다. AI 라벨과 검수 원본을 분리해 저장해야 운영 중 분류 기준을 수정하고 결과를 비교할 수 있었습니다. 내부 평가표와 원시 데이터는 공개하지 않습니다.
